# Feature Specification: 실시간 채팅 앱

**Feature Branch**: `001-realtime-chat`
**Created**: 2026-01-21
**Status**: Draft
**Input**: User description: "나는 이제 채팅앱을 만들거야. 사용자 시나리오를 알려줄게.
- 로비에서 사용자는 닉네임을 입력하거나 그냥 시작할 수 있다.
- 닉네임을 입력하지 않았다면 랜덤닉네임을 부여한다.
- 로비에서 닉네임 단계를 끝냈다면 메인페이지에서 방 리스트를 볼 수 있다.
- 로비에서 사용자는 방을 만들거나 방을 클릭하여 입장할 수 있다.
- 로비에서 방 아이템은 사용자 리스트와 카운트(1/5) 의 정보를 가지고 있다.
- 방 개별 페이지에서는 사용자들이 실시간으로 채팅을 주고 받을 수 있다.
- 방 개별 페이지에서 채팅 읽음 표시등은 하지 않는다.
- 방은 수동으로 삭제되는 것이 아닌 모든 사용자가 방에서 나가 아무도 없다면 방이 실시간 자동 삭제된다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 사용자 로비 입장 및 닉네임 설정 (Priority: P1)

사용자는 채팅 앱에 처음 접속하여 자신만의 닉네임을 설정하고 채팅 로비로 입장한다.

**Why this priority**: 모든 채팅 기능의 기초가 되는 사용자 신원 설정으로, 이것 없이는 다른 기능을 사용할 수 없는 필수 기능

**Independent Test**: 사용자가 앱에 접속하여 닉네임을 입력하거나 생략하고 로비 화면에 도달하는지 확인할 수 있으며, 랜덤 닉네임 생성도 독립적으로 검증 가능

**Acceptance Scenarios**:

1. **Given** 사용자가 앱에 처음 접속했을 때, **When** 원하는 닉네임을 입력하고 시작 버튼을 누르면, **Then** 해당 닉네임으로 로비에 입장한다
2. **Given** 사용자가 앱에 접속했을 때, **When** 닉네임을 입력하지 않고 시작 버튼을 누르면, **Then** 시스템이 자동으로 형용사+명사 조합의 랜덤 닉네임(예: "친절한고양이")을 부여하고 로비에 입장한다
3. **Given** 사용자가 닉네임을 설정했을 때, **When** 로비 화면으로 이동하면, **Then** 설정된 닉네임이 화면에 표시된다

---

### User Story 2 - 실시간 채팅 기능 (Priority: P1)

사용자는 채팅방 내에서 다른 참여자들과 실시간으로 메시지를 주고받으며 대화를 나눌 수 있다.

**Why this priority**: 채팅 앱의 핵심 기능으로, 이것이 없으면 앱의 존재 가치가 없는 필수 기능

**Independent Test**: 한 사용자가 메시지를 보내면 같은 방의 다른 사용자들에게 실시간으로 표시되는지 확인하여 독립적으로 검증 가능

**Acceptance Scenarios**:

1. **Given** 사용자가 채팅방에 있을 때, **When** 메시지를 입력하고 전송하면, **Then** 해당 메시지가 즉시 채팅 창에 표시된다
2. **Given** 다른 사용자가 메시지를 보냈을 때, **When** 채팅방에 있는 모든 참여자가 확인하면, **Then** 실시간으로 새 메시지가 표시된다
3. **Given** 사용자가 채팅방에서 메시지를 보낼 때, **When** 전송 버튼을 클릭하거나 엔터키를 누르면, **Then** 메시지가 다른 참여자들에게 즉시 전달된다

---

### User Story 3 - 채팅방 목록 조회 및 관리 (Priority: P2)

사용자는 로비에서 현재 활성화된 채팅방들의 목록을 확인하고, 각 방의 참여자 정보와 현재 인원수를 파악할 수 있다.

**Why this priority**: 사용자가 참여할 방을 선택하기 위한 핵심 정보 제공 기능으로, 채팅방 선택의 기반이 됨

**Independent Test**: 로비 화면에서 방 목록이 표시되고, 각 방의 참여자 명단과 인원수 표시(예: 3/5)가 정확히 작동하는지 독립적으로 확인 가능

**Acceptance Scenarios**:

1. **Given** 사용자가 로비에 있을 때, **When** 화면을 확인하면, **Then** 현재 활성화된 모든 채팅방 목록이 최신 활동 순으로 정렬되어 표시된다
2. **Given** 채팅방이 존재할 때, **When** 방 목록을 확인하면, **Then** 각 방의 현재 참여자 목록과 인원수가 "현재인원/최대인원" 형태로 표시된다
3. **Given** 모든 사용자가 특정 방을 나갔을 때, **When** 방 목록을 새로고침하면, **Then** 해당 방이 자동으로 목록에서 삭제된다

---

### User Story 4 - 새로운 채팅방 생성 (Priority: P2)

사용자는 로비에서 새로운 채팅방을 생성하여 다른 사용자들을 초대하고 대화를 시작할 수 있다.

**Why this priority**: 사용자가 원하는 주제나 목적으로 새로운 대화를 시작할 수 있게 하는 능동적 기능

**Independent Test**: 사용자가 방 생성 버튼을 클릭하고 새로운 방이 생성되어 목록에 추가되며, 해당 방으로 자동 입장하는지 확인 가능

**Acceptance Scenarios**:

1. **Given** 사용자가 로비에 있을 때, **When** "새 방 만들기" 버튼을 클릭하면, **Then** 새로운 채팅방이 생성되고 해당 방으로 자동 입장한다
2. **Given** 새 방이 생성되었을 때, **When** 다른 사용자가 로비를 확인하면, **Then** 새로 생성된 방이 방 목록에 표시된다
3. **Given** 방을 생성한 사용자가 있을 때, **When** 방 목록을 확인하면, **Then** 해당 방의 참여자 수가 "1/5"로 표시된다

---

### User Story 5 - 기존 채팅방 참여 (Priority: P2)

사용자는 로비의 방 목록에서 원하는 채팅방을 선택하여 참여하고 진행 중인 대화에 합류할 수 있다.

**Why this priority**: 이미 활성화된 커뮤니티에 참여할 수 있게 하는 사회적 기능

**Independent Test**: 사용자가 방 목록에서 특정 방을 클릭하고 해당 방으로 입장하여 기존 대화 내용을 확인할 수 있는지 검증 가능

**Acceptance Scenarios**:

1. **Given** 활성화된 채팅방이 존재할 때, **When** 사용자가 방 목록에서 특정 방을 클릭하면, **Then** 해당 방으로 입장하여 채팅 화면이 표시된다
2. **Given** 사용자가 방에 입장했을 때, **When** 채팅 화면을 확인하면, **Then** 이전 대화 내용이 표시된다
3. **Given** 새 사용자가 방에 입장했을 때, **When** 다른 참여자가 화면을 확인하면, **Then** 참여자 수가 업데이트되어 표시된다

---

### User Story 6 - 채팅방 자동 삭제 시스템 (Priority: P3)

시스템은 모든 참여자가 채팅방을 나간 경우 해당 방을 자동으로 삭제하여 불필요한 빈 방들이 누적되지 않도록 관리한다.

**Why this priority**: 시스템 운영 효율성을 위한 자동화 기능으로, 사용자 경험에 직접적 영향은 적지만 장기적 시스템 관리에 중요

**Independent Test**: 방의 마지막 참여자가 나간 후 해당 방이 방 목록에서 자동으로 사라지는지 확인하여 독립적으로 검증 가능

**Acceptance Scenarios**:

1. **Given** 채팅방에 한 명의 참여자만 남아있을 때, **When** 마지막 참여자가 방을 나가면, **Then** 해당 방이 자동으로 삭제된다
2. **Given** 방이 자동 삭제되었을 때, **When** 다른 사용자가 로비를 확인하면, **Then** 삭제된 방이 방 목록에서 더 이상 표시되지 않는다
3. **Given** 빈 방이 삭제되었을 때, **When** 시스템을 확인하면, **Then** 해당 방의 모든 데이터가 완전히 제거된다

---

### Edge Cases

- 사용자가 닉네임을 매우 길게 입력했을 때 어떻게 처리할 것인가?
- 동시에 여러 사용자가 같은 방에 입장하려고 할 때 인원 제한을 어떻게 관리할 것인가?
- 네트워크 연결이 불안정할 때 메시지 전송 실패를 어떻게 처리할 것인가?
- 방 최대 인원에 도달했을 때 추가 참여 시도를 어떻게 처리할 것인가?
- 사용자가 브라우저를 갑작스럽게 닫거나 네트워크가 끊어진 후 30초 내에 다시 접속했을 때 어떻게 처리할 것인가?
- 사용자가 500자 제한을 초과하는 메시지를 입력했을 때 어떻게 처리할 것인가?

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 사용자가 닉네임을 입력할 수 있는 로비 화면을 제공해야 함
- **FR-002**: 시스템은 닉네임이 입력되지 않은 경우 형용사+명사 조합의 랜덤 닉네임을 자동 생성해야 함 (예: "친절한고양이")
- **FR-003**: 시스템은 현재 활성화된 모든 채팅방 목록을 최신 활동 순으로 정렬하여 실시간으로 표시해야 함
- **FR-004**: 시스템은 각 채팅방의 현재 참여자 목록과 인원수를 "현재인원/최대인원" 형태로 표시해야 함
- **FR-005**: 시스템은 사용자가 새로운 채팅방을 생성할 수 있는 기능을 제공해야 함
- **FR-006**: 시스템은 사용자가 기존 채팅방에 참여할 수 있는 기능을 제공해야 함
- **FR-007**: 시스템은 채팅방 내에서 실시간 메시지 전송 및 수신 기능을 제공해야 함
- **FR-008**: 시스템은 모든 참여자가 나간 채팅방을 자동으로 삭제해야 함
- **FR-009**: 시스템은 채팅방별로 최대 5명까지의 참여자 제한을 적용해야 함
- **FR-010**: 시스템은 메시지 읽음 표시 기능을 제공하지 않아야 함
- **FR-011**: 시스템은 사용자의 방 입장 및 퇴장을 실시간으로 다른 참여자들에게 반영해야 함
- **FR-012**: 시스템은 닉네임 길이를 최대 20자로 제한하고 한글, 영문, 숫자, 공백만 허용해야 함
- **FR-013**: 시스템은 새 채팅방 생성 시 자동으로 고유한 순번을 부여하여 "채팅방 #001" 형태의 이름을 생성해야 함
- **FR-014**: 시스템은 사용자가 입력할 수 있는 메시지의 최대 길이를 500자로 제한해야 함
- **FR-015**: 시스템은 사용자 연결 끊김을 감지하고 30초 후 해당 사용자를 채팅방에서 자동 제거해야 함

### Key Entities

- **사용자**: 채팅 앱을 이용하는 개인으로, 사용자 입력 또는 자동 생성(형용사+명사 조합)된 닉네임을 가지며 여러 채팅방에 참여할 수 있음
- **채팅방**: 최대 5명의 사용자가 참여하여 실시간 대화를 나눌 수 있는 공간으로, 자동 생성된 고유 이름(예: "채팅방 #001"), 참여자 목록, 메시지 히스토리를 포함함
- **메시지**: 사용자가 채팅방에서 보내는 텍스트 데이터로, 최대 500자 제한, 발신자 정보와 전송 시간을 포함함

## Clarifications

### Session 2026-01-21

- Q: 채팅방 이름 및 식별 방식 → A: 자동 생성된 고유 이름 (예: "채팅방 #001", "채팅방 #002")
- Q: 메시지 길이 제한 → A: 500자 제한
- Q: 랜덤 닉네임 생성 규칙 → A: 형용사+명사 조합 (예: "친절한고양이", "빠른토끼")
- Q: 사용자 연결 끊김 감지 시간 → A: 30초 후 제거
- Q: 채팅방 목록 정렬 방식 → A: 최신 활동 순 (가장 최근에 메시지가 전송된 순)

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자가 앱 접속부터 채팅방 입장까지 30초 이내에 완료할 수 있어야 함
- **SC-002**: 메시지 전송 후 다른 참여자에게 1초 이내에 표시되어야 함
- **SC-003**: 동시 접속자 100명까지 원활한 서비스 제공이 가능해야 함
- **SC-004**: 방 참여자 변경사항이 5초 이내에 모든 참여자에게 반영되어야 함
- **SC-005**: 빈 방 자동 삭제가 마지막 참여자 퇴장 후 10초 이내에 실행되어야 함
- **SC-006**: 사용자의 95% 이상이 첫 번째 시도에서 성공적으로 채팅방에 참여할 수 있어야 함
- **SC-007**: 사용자 연결 끊김 감지 후 30초 이내에 해당 사용자가 채팅방에서 제거되어야 함

## Assumptions

- 사용자는 현대적인 웹 브라우저를 사용한다고 가정함
- 닉네임은 중복을 허용하며, 같은 닉네임의 여러 사용자가 동시에 접속할 수 있음
- 채팅 메시지는 텍스트만 지원하며, 이미지나 파일 첨부 기능은 포함하지 않음
- 채팅방의 이전 대화 내용은 세션 동안만 유지되며, 영구적으로 저장되지 않음
- 채팅방은 시스템에서 자동으로 고유한 순번을 부여받아 "채팅방 #001" 형태의 이름을 가짐
- 사용자 연결 상태는 실시간으로 모니터링되며, 연결 끊김 후 30초가 경과하면 해당 사용자는 자동으로 채팅방에서 제거됨
