## User Scenarios & Testing *(mandatory)*

### User Story 1 - 노트 작성 (Priority: P1)

사용자는 새로운 노트를 작성하고 저장할 수 있다. 노트 작성 화면에서 제목과 본문을 입력하고 카테고리를 선택한 뒤 저장 버튼을 눌러 노트를 생성한다. 저장된 노트는 즉시 노트 목록에 반영된다.

**Why this priority**: 노트 앱의 핵심 가치는 노트를 작성하고 저장하는 것이다. 이 기능 없이는 앱의 존재 의미가 없으므로 최우선 순위이다.

**Independent Test**: 앱을 열고 "새 노트 작성" 버튼을 누른 후 제목/본문을 입력하고 저장하면, 노트 목록에서 방금 작성한 노트를 확인할 수 있다.

**Acceptance Scenarios**:

1. **Given** 사용자가 노트 작성 화면에 있을 때, **When** 제목 "회의록"과 본문 "오늘 회의 내용 정리"를 입력하고 저장 버튼을 누르면, **Then** 노트가 저장되고 노트 목록 화면으로 돌아가며 "회의록" 노트가 목록 최상단에 표시된다.
2. **Given** 사용자가 노트 작성 화면에 있을 때, **When** 제목을 입력하지 않고 저장 버튼을 누르면, **Then** "제목을 입력해주세요" 안내 메시지가 표시되고 노트는 저장되지 않는다.
3. **Given** 사용자가 노트 작성 중일 때, **When** 카테고리 "업무"를 선택하고 저장하면, **Then** 노트가 "업무" 카테고리와 함께 저장된다.
4. **Given** 사용자가 노트를 작성 중일 때, **When** 뒤로가기를 누르면, **Then** "작성 중인 내용이 있습니다. 나가시겠습니까?" 확인 대화상자가 표시된다.

### User Story 2 - 노트 목록 조회 (Priority: P1)

사용자는 저장된 노트 목록을 확인할 수 있다. 홈 화면에서 모든 노트가 최신순으로 정렬되어 표시되며, 각 노트의 제목, 카테고리, 작성일이 보인다. 노트가 없는 경우 빈 상태 안내가 표시된다.

**Why this priority**: 노트 목록 조회는 노트 작성과 함께 앱의 가장 기본적인 기능이다. 목록이 없으면 사용자가 노트를 찾을 수 없다.

**Independent Test**: 앱을 열면 저장된 노트들이 목록으로 표시되며, 각 노트의 제목과 카테고리, 작성일을 확인할 수 있다.

**Acceptance Scenarios**:

1. **Given** 저장된 노트가 3개 이상 있을 때, **When** 홈 화면에 진입하면, **Then** 모든 노트가 최신 작성일순으로 표시된다.
2. **Given** 저장된 노트가 없을 때, **When** 홈 화면에 진입하면, **Then** "아직 작성된 노트가 없습니다" 빈 상태 안내와 함께 "첫 노트 작성하기" 유도 버튼이 표시된다.
3. **Given** 노트 목록이 표시되어 있을 때, **When** 특정 노트를 클릭하면, **Then** 해당 노트의 상세 보기 화면으로 이동한다.

---

### User Story 3 - 노트 상세 보기 (Priority: P2)

사용자는 특정 노트의 전체 내용을 읽기 전용으로 확인할 수 있다. 상세 화면에서 제목, 본문, 카테고리, 작성일, 수정일 등 노트의 모든 정보가 표시된다.

**Why this priority**: 노트를 작성한 후 다시 읽어보는 것은 핵심 사용 흐름의 일부이다. 작성 기능(P1) 다음으로 중요하다.

**Independent Test**: 노트 목록에서 특정 노트를 선택하면 해당 노트의 제목, 본문, 카테고리, 작성일 등이 전체 표시된다.

**Acceptance Scenarios**:

1. **Given** 노트 목록 화면에서, **When** "회의록" 노트를 클릭하면, **Then** 노트 상세 화면에 제목 "회의록", 본문 내용, 카테고리 "업무", 작성일시가 모두 표시된다.
2. **Given** 노트 상세 화면에서, **When** "편집" 버튼을 누르면, **Then** 노트 편집 화면으로 전환된다.
3. **Given** 노트 상세 화면에서, **When** "삭제" 버튼을 누르면, **Then** "이 노트를 삭제하시겠습니까?" 확인 대화상자가 표시된다.

---

### User Story 4 - 노트 편집 (Priority: P2)

사용자는 기존 노트의 제목, 본문, 카테고리를 수정할 수 있다. 수정 후 저장하면 변경 사항이 반영되고, 수정일이 업데이트된다.

**Why this priority**: 노트를 수정하는 것은 작성 다음으로 자주 사용되는 기능이며, 작성 기능의 자연스러운 확장이다.

**Independent Test**: 기존 노트를 선택하고 편집 화면에서 내용을 수정한 뒤 저장하면, 변경된 내용이 상세 화면과 목록에 즉시 반영된다.

**Acceptance Scenarios**:

1. **Given** "회의록" 노트의 편집 화면에서, **When** 제목을 "팀 회의록"으로 변경하고 저장하면, **Then** 노트 상세 화면에서 제목이 "팀 회의록"으로 표시되고 수정일이 현재 시각으로 업데이트된다.
2. **Given** 노트 편집 화면에서, **When** 카테고리를 "업무"에서 "개인"으로 변경하고 저장하면, **Then** 변경된 카테고리가 반영된다.
3. **Given** 노트 편집 중, **When** 변경 사항 없이 저장을 누르면, **Then** 수정일이 변경되지 않고 상세 화면으로 돌아간다.

---

### User Story 5 - 노트 삭제 (Priority: P2)

사용자는 더 이상 필요하지 않은 노트를 삭제할 수 있다. 삭제 시 확인 단계를 거치며, 삭제된 노트는 목록에서 즉시 사라진다.

**Why this priority**: CRUD의 일부로서 기본 기능을 완성하는 데 필요하다.

**Independent Test**: 노트 상세 화면에서 삭제 버튼을 누르고 확인하면, 해당 노트가 목록에서 사라진다.

**Acceptance Scenarios**:

1. **Given** "회의록" 노트의 상세 화면에서, **When** 삭제 버튼을 누르고 확인 대화상자에서 "삭제"를 선택하면, **Then** 노트가 삭제되고 노트 목록으로 돌아가며 "회의록" 노트가 목록에 없다.
2. **Given** 삭제 확인 대화상자에서, **When** "취소"를 선택하면, **Then** 노트는 삭제되지 않고 상세 화면이 유지된다.

---

### User Story 6 - 카테고리 관리 (Priority: P3)

사용자는 노트를 분류하기 위한 카테고리를 생성, 조회, 삭제할 수 있다. 카테고리를 통해 노트를 체계적으로 관리한다. 기본 카테고리("전체", "미분류")는 삭제할 수 없다.

**Why this priority**: 카테고리는 노트 분류의 핵심 도구이지만, 카테고리 없이도 노트 작성/조회는 가능하므로 P3이다.

**Independent Test**: 카테고리 관리 화면에서 "독서"라는 카테고리를 새로 만들면, 노트 작성 시 카테고리 선택에 "독서"가 나타난다.

**Acceptance Scenarios**:

1. **Given** 카테고리 관리 화면에서, **When** 새 카테고리 이름 "독서"를 입력하고 추가하면, **Then** 카테고리 목록에 "독서"가 추가된다.
2. **Given** 카테고리 목록에 "독서"가 있을 때, **When** "독서" 카테고리의 삭제 버튼을 누르면, **Then** 해당 카테고리에 속한 노트가 있는 경우 "이 카테고리에 N개의 노트가 있습니다. 노트는 '미분류'로 이동됩니다." 안내 후 확인하면 삭제된다.
3. **Given** 카테고리 관리 화면에서, **When** "전체" 또는 "미분류" 카테고리의 삭제를 시도하면, **Then** 삭제 버튼이 비활성화되어 있거나 삭제가 불가능하다는 안내가 표시된다.

---

### User Story 7 - 카테고리별 노트 필터링 (Priority: P3)

사용자는 특정 카테고리의 노트만 필터링하여 볼 수 있다. 홈 화면의 카테고리 탭 또는 필터를 통해 원하는 카테고리의 노트만 조회한다.

**Why this priority**: 노트가 많아지면 카테고리별 필터링이 필요하지만, 기본 목록 조회(P1)만으로도 앱은 사용 가능하다.

**Independent Test**: 홈 화면에서 "업무" 카테고리를 선택하면 "업무" 카테고리에 속한 노트만 표시된다.

**Acceptance Scenarios**:

1. **Given** 다양한 카테고리의 노트가 있을 때, **When** "업무" 카테고리 필터를 선택하면, **Then** "업무" 카테고리의 노트만 표시된다.
2. **Given** "업무" 필터가 적용된 상태에서, **When** "전체" 필터를 선택하면, **Then** 모든 노트가 다시 표시된다.
3. **Given** "독서" 카테고리에 노트가 없을 때, **When** "독서" 필터를 선택하면, **Then** "이 카테고리에 노트가 없습니다" 빈 상태 안내가 표시된다.

---

### User Story 8 - 노트 검색 (Priority: P3)

사용자는 키워드로 노트를 검색할 수 있다. 검색어는 노트의 제목과 본문에서 일치하는 결과를 반환한다.

**Why this priority**: 검색 기능은 노트가 많아졌을 때 편의성을 크게 높이지만, 기본 목록과 필터링만으로도 앱 사용은 가능하다.

**Independent Test**: 검색창에 "회의"를 입력하면 제목 또는 본문에 "회의"가 포함된 노트만 표시된다.

**Acceptance Scenarios**:

1. **Given** 홈 화면에서, **When** 검색창에 "회의"를 입력하면, **Then** 제목 또는 본문에 "회의"가 포함된 노트만 표시된다.
2. **Given** 검색 결과가 없을 때, **When** "xyz123"을 검색하면, **Then** "검색 결과가 없습니다" 안내가 표시된다.
3. **Given** 검색 결과가 표시된 상태에서, **When** 검색어를 모두 지우면, **Then** 전체 노트 목록이 다시 표시된다.

---

### User Story 9 - 사이드바 네비게이션 (Priority: P3)

사용자는 사이드바를 통해 앱의 주요 화면(홈, 카테고리 관리)으로 쉽게 이동할 수 있다. 사이드바에는 카테고리 목록이 표시되어 빠른 필터링도 가능하다.

**Why this priority**: 네비게이션은 사용성을 높이는 요소이지만, 기본 화면 전환만으로도 앱의 핵심 기능은 사용 가능하다.

**Independent Test**: 사이드바에서 "카테고리 관리"를 클릭하면 카테고리 관리 화면으로 이동하고, 특정 카테고리를 클릭하면 해당 카테고리 노트만 필터링된다.

**Acceptance Scenarios**:

1. **Given** 어떤 화면에서든, **When** 사이드바의 "홈" 메뉴를 클릭하면, **Then** 전체 노트 목록이 표시된 홈 화면으로 이동한다.
2. **Given** 사이드바가 표시되어 있을 때, **When** 사이드바의 카테고리 목록에서 "업무"를 클릭하면, **Then** 홈 화면에서 "업무" 카테고리 노트만 필터링되어 표시된다.
3. **Given** 모바일 화면 크기에서, **When** 메뉴 아이콘을 누르면, **Then** 사이드바가 오버레이로 나타나며, 외부 영역을 클릭하면 닫힌다.

---

### Edge Cases

- 매우 긴 제목(200자 이상)을 입력한 경우 어떻게 표시되는가? → 최대 100자로 제한하며, 목록에서는 말줄임표(...)로 표시
- 매우 긴 본문(10,000자 이상)을 입력한 경우 성능 문제가 있는가? → 본문은 최대 50,000자로 제한하며, 해당 범위 내에서는 정상 동작
- 동일한 이름의 카테고리를 중복 생성하려는 경우 → "이미 존재하는 카테고리입니다" 안내 후 생성 차단
- 네트워크가 불안정한 상태에서 노트 저장 시 → 저장 실패 안내와 재시도 옵션 제공
- 카테고리 삭제 시 해당 카테고리에 속한 노트가 대량(100개 이상)일 때 → 확인 대화상자에 정확한 노트 수를 안내하고, 모든 노트를 "미분류"로 이동
- 빈 문자열이나 공백만으로 카테고리를 생성하려는 경우 → 유효성 검사로 차단, "카테고리 이름을 입력해주세요" 안내
- 노트 편집 중 다른 기기에서 동일 노트를 수정한 경우 → 단일 사용자 환경을 가정하므로 고려하지 않음 (Assumptions 참조)

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 사용자가 제목, 본문, 카테고리를 포함한 노트를 생성할 수 있어야 한다
- **FR-002**: 시스템은 노트 목록을 최신순으로 정렬하여 표시해야 한다
- **FR-003**: 시스템은 개별 노트의 전체 내용을 상세 화면에서 표시해야 한다
- **FR-004**: 시스템은 기존 노트의 제목, 본문, 카테고리를 수정할 수 있어야 한다
- **FR-005**: 시스템은 확인 단계를 거쳐 노트를 삭제할 수 있어야 한다
- **FR-006**: 시스템은 노트의 작성일과 수정일을 자동으로 기록하고 표시해야 한다
- **FR-007**: 시스템은 카테고리의 생성, 조회, 삭제 기능을 제공해야 한다
- **FR-008**: 시스템은 기본 카테고리("전체", "미분류")를 제공하며, 이는 삭제할 수 없어야 한다
- **FR-009**: 시스템은 카테고리별로 노트를 필터링하여 표시할 수 있어야 한다
- **FR-010**: 시스템은 노트 제목과 본문에서 키워드 검색 기능을 제공해야 한다
- **FR-011**: 시스템은 사이드바 네비게이션을 통해 주요 화면 이동과 카테고리 필터링을 지원해야 한다
- **FR-012**: 시스템은 노트 제목을 최대 100자로 제한해야 한다
- **FR-013**: 시스템은 노트 본문을 최대 50,000자로 제한해야 한다
- **FR-014**: 시스템은 중복된 카테고리 이름의 생성을 차단해야 한다
- **FR-015**: 시스템은 카테고리 삭제 시 해당 카테고리의 노트를 "미분류"로 자동 이동시켜야 한다
- **FR-016**: 시스템은 노트 작성/편집 중 이탈 시 확인 대화상자를 표시해야 한다
- **FR-017**: 시스템은 저장 실패 시 사용자에게 오류 안내와 재시도 옵션을 제공해야 한다
- **FR-018**: 시스템은 반응형 레이아웃을 지원하여 데스크톱과 모바일 모두에서 사용 가능해야 한다

### Key Entities

- **노트(Note)**: 사용자가 작성한 메모. 제목(필수, 최대 100자), 본문(선택, 최대 50,000자), 카테고리(하나, 기본값 "미분류"), 작성일, 수정일을 포함한다. 하나의 카테고리에 속한다.
- **카테고리(Category)**: 노트를 분류하는 태그. 이름(필수, 고유), 기본 여부(삭제 불가 플래그)를 포함한다. 여러 노트가 하나의 카테고리에 속할 수 있다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자가 노트 작성을 시작하고 저장 완료까지 30초 이내에 수행할 수 있다
- **SC-002**: 노트 목록에서 원하는 노트를 찾아 상세 내용을 확인하기까지 3번 이하의 클릭으로 도달할 수 있다
- **SC-003**: 100개 이상의 노트가 있어도 목록 화면이 2초 이내에 로드된다
- **SC-004**: 검색어 입력 후 500밀리초 이내에 검색 결과가 표시된다
- **SC-005**: 카테고리 필터 선택 시 500밀리초 이내에 필터링 결과가 표시된다
- **SC-006**: 데스크톱(1024px 이상)과 모바일(320px~768px) 환경에서 모든 기능이 정상 동작한다
- **SC-007**: 노트의 생성, 수정, 삭제 작업이 완료된 후 목록에 즉시(1초 이내) 반영된다

## Assumptions

- 이 앱은 **단일 사용자 환경**을 대상으로 한다. 멀티 유저, 로그인, 권한 관리 기능은 포함하지 않는다.
- 데이터는 서버 API를 통해 저장/조회된다고 가정하며, 실제 백엔드는 Mock API로 대체한다.
- 브라우저 호환성: 최신 Chrome, Firefox, Safari, Edge를 지원한다.
- 오프라인 기능은 고려하지 않는다.
- 파일 첨부, 이미지 삽입, 리치 텍스트 편집 등 고급 에디터 기능은 범위에 포함하지 않는다. 본문은 플레인 텍스트로 한정한다.

## E2E Test Scenarios *(mandatory)*

### E2E Scenarios for User Story 1 (노트 작성)

- **E2E-US1-001**: 사용자가 홈 화면에서 "새 노트 작성" 버튼을 누르고, 제목과 본문을 입력하고, 카테고리를 선택한 뒤 저장하면, 노트 목록에서 방금 작성한 노트를 확인할 수 있다
- **E2E-US1-002**: 제목 없이 노트를 저장하려 하면 유효성 검사 오류가 표시되고 저장되지 않는다

### E2E Scenarios for User Story 2 (노트 목록 조회)

- **E2E-US2-001**: 여러 노트가 저장된 상태에서 홈 화면에 진입하면, 모든 노트가 최신순으로 표시된다
- **E2E-US2-002**: 노트가 없는 상태에서 홈 화면에 진입하면, 빈 상태 안내와 작성 유도 버튼이 표시된다

### E2E Scenarios for User Story 3 (노트 상세 보기)

- **E2E-US3-001**: 노트 목록에서 특정 노트를 클릭하면 제목, 본문, 카테고리, 작성일이 모두 표시되는 상세 화면으로 이동한다

### E2E Scenarios for User Story 4 (노트 편집)

- **E2E-US4-001**: 노트 상세 화면에서 편집 모드로 진입하여 제목을 변경하고 저장하면, 변경된 제목이 상세 화면과 목록에 반영된다

### E2E Scenarios for User Story 5 (노트 삭제)

- **E2E-US5-001**: 노트 상세 화면에서 삭제 버튼을 누르고 확인하면, 해당 노트가 삭제되고 목록에서 사라진다
- **E2E-US5-002**: 삭제 확인 대화상자에서 취소를 선택하면 노트가 유지된다

### E2E Scenarios for User Story 6 (카테고리 관리)

- **E2E-US6-001**: 카테고리 관리 화면에서 새 카테고리를 생성하고, 노트 작성 시 해당 카테고리를 선택할 수 있다
- **E2E-US6-002**: 노트가 있는 카테고리를 삭제하면, 해당 노트가 "미분류"로 이동된다

### E2E Scenarios for User Story 7 (카테고리별 필터링)

- **E2E-US7-001**: 홈 화면에서 카테고리 필터를 선택하면 해당 카테고리의 노트만 표시되고, "전체"를 선택하면 모든 노트가 표시된다

### E2E Scenarios for User Story 8 (노트 검색)

- **E2E-US8-001**: 검색창에 키워드를 입력하면 제목 또는 본문에 해당 키워드가 포함된 노트만 표시되고, 검색어를 지우면 전체 목록이 복원된다

### E2E Scenarios for User Story 9 (사이드바 네비게이션)

- **E2E-US9-001**: 사이드바에서 각 메뉴와 카테고리를 클릭하여 해당 화면 또는 필터로 전환되는 전체 네비게이션 플로우를 확인한다

### Cross-Story E2E Scenarios

- **E2E-INT-001**: 사용자가 카테고리를 생성하고 → 해당 카테고리로 노트를 작성하고 → 노트를 편집하고 → 검색으로 찾고 → 삭제하는 전체 워크플로우가 정상 동작한다
- **E2E-INT-002**: 카테고리를 삭제했을 때 해당 카테고리의 노트가 "미분류"로 이동하고, "미분류" 필터에서 해당 노트를 확인할 수 있다
